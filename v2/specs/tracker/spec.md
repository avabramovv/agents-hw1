
# Tracker Specification

## ADDED Requirements

### Requirement: Модель задачи

Система MUST представлять каждую задачу объектом с полями:

- `id` — уникальный идентификатор задачи.
- `title` — название задачи.
- `hours` — оценка в часах.
- `done` — булев статус выполнения.

#### Scenario: Начальное состояние

- **WHEN** приложение запускается с начальными данными
- **THEN** список содержит «Чтение» (2 ч, готово), «Практика» (4 ч, активно) и «Повторение» (2 ч, активно)
- **AND** суммарное время равно 8 ч
- **AND** выполненное время равно 2 ч
- **AND** прогресс равен 25%.

### Requirement: Управление задачами

Система MUST поддерживать добавление, удаление и переключение статуса задачи.

Каждое действие MUST изменять данные приложения, а не только визуальное представление.

#### Scenario: Добавление задачи

- **WHEN** пользователь вводит корректные название и часы и нажимает кнопку добавления
- **THEN** новая задача появляется в данных приложения
- **AND** итоговые показатели пересчитываются
- **AND** видимый список соответствует текущему фильтру.

#### Scenario: Удаление задачи

- **WHEN** пользователь удаляет задачу
- **THEN** задача исключается из данных приложения
- **AND** список и итоговые показатели обновляются.

#### Scenario: Переключение done

- **WHEN** пользователь меняет состояние выполнения задачи
- **THEN** значение `done` изменяется на противоположное
- **AND** выполненные часы и прогресс пересчитываются.

### Requirement: Валидация названия

Система MUST удалять пробелы по краям названия перед проверкой.

Название после `trim` MUST быть непустым.

#### Scenario: Пустое название

- **WHEN** пользователь вводит пустое название или только пробелы
- **THEN** задача не добавляется
- **AND** рядом с полем названия появляется сообщение об ошибке
- **AND** значения формы сохраняются.

### Requirement: Валидация часов

Значение `hours` MUST:
- Быть числом.
- Находиться в диапазоне от 0,5 до 24 включительно.
- Быть кратным 0,5.

Пустое значение MUST считаться некорректным и MUST NOT интерпретироваться как ноль.

#### Scenario: Пустые часы

- **WHEN** пользователь оставляет поле часов пустым
- **THEN** задача не добавляется
- **AND** рядом с полем часов появляется ошибка
- **AND** значения формы сохраняются.

#### Scenario: Отрицательные часы

- **WHEN** пользователь вводит отрицательное количество часов
- **THEN** задача не добавляется
- **AND** рядом с полем часов появляется ошибка.

#### Scenario: Некорректный диапазон или шаг

- **WHEN** часы меньше 0,5, больше 24, не являются числом или не кратны 0,5
- **THEN** задача не добавляется
- **AND** рядом с полем часов появляется ошибка.

#### Scenario: Корректная граница

- **WHEN** пользователь вводит 0,5 или 24 часа с непустым названием
- **THEN** задача успешно добавляется.

### Requirement: Расчёт итогов

Система MUST вычислять:

- `totalHours` — сумму часов всех задач.
- `doneHours` — сумму часов задач с `done = true`.
- `progress` — округлённый процент выполнения.

Формула:

`progress = round(100 × doneHours / totalHours)`

Если `totalHours = 0`, прогресс MUST равняться 0%.

Система MUST NOT показывать `NaN` или `Infinity`.

#### Scenario: Исходный прогресс

- **WHEN** загружены три стартовые задачи
- **THEN** `totalHours = 8`
- **AND** `doneHours = 2`
- **AND** `progress = 25%`.

#### Scenario: Практика выполнена

- **WHEN** пользователь отмечает «Практику» готовой
- **THEN** `doneHours = 6`
- **AND** `totalHours = 8`
- **AND** `progress = 75%`.

#### Scenario: Все задачи удалены

- **WHEN** пользователь удаляет все задачи
- **THEN** `totalHours = 0`
- **AND** `doneHours = 0`
- **AND** `progress = 0%`
- **AND** отсутствуют `NaN` и `Infinity`.

### Requirement: Фильтрация

Система MUST поддерживать три фильтра:

- «Все» — все задачи.
- «Активные» — задачи с `done = false`.
- «Готовые» — задачи с `done = true`.

Фильтр MUST влиять только на видимый список.

Итоговые часы и процент выполнения MUST вычисляться по всем задачам независимо от фильтра.

#### Scenario: Фильтр активных задач

- **WHEN** в начальном состоянии включён фильтр «Активные»
- **THEN** видны «Практика» и «Повторение»
- **AND** «Чтение» не отображается в списке
- **AND** суммарное время остаётся 8 ч
- **AND** прогресс остаётся 25%.

#### Scenario: Фильтр готовых задач

- **WHEN** в начальном состоянии включён фильтр «Готовые»
- **THEN** отображается только «Чтение»
- **AND** итоговые показатели не изменяются.

### Requirement: Интерфейс

Система MUST обеспечивать читаемый интерфейс на ширине 390 px без горизонтальной прокрутки.

Поля ввода и кнопки MUST иметь понятные подписи.

Ошибки валидации MUST отображаться рядом с соответствующими полями.

#### Scenario: Мобильная ширина

- **WHEN** приложение открыто в окне шириной 390 px
- **THEN** текст и элементы управления остаются читаемыми
- **AND** горизонтальная прокрутка отсутствует.

### Requirement: Автономность

Система MUST работать без CDN, внешних библиотек и API-ключей.

Для варианта A система MUST размещать HTML, CSS и JavaScript внутри `tracker-v2.html`.

Для варианта B система MUST использовать файлы `index.html`, `styles.css`, `app.mjs`, `domain.mjs` и `tests/acceptance.test.mjs`.

### Requirement: Необязательное сохранение данных

Если реализовано сохранение, система MUST использовать `localStorage`.

Недоступность `localStorage` MUST NOT препятствовать работе приложения.

#### Scenario: Хранилище недоступно

- **WHEN** приложение не может использовать `localStorage`
- **THEN** отображается понятное сообщение
- **AND** приложение продолжает работать в памяти
- **AND** управление задачами остаётся доступным.
