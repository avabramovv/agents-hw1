
# Design: Мини-трекер учебных задач

## 1. Архитектура

Приложение работает в браузере, без сервера и внешних зависимостей.

Основные части:

1. Данные задач.
2. Операции изменения данных.
3. Валидация пользовательского ввода.
4. Расчёт итоговых показателей.
5. Фильтрация видимого списка.
6. Отображение интерфейса.

## 2. Структура данных

Каждая задача имеет поля:

| Поле | Тип | Назначение |
|---|---|---|
| id | уникальный идентификатор | Поиск и изменение задачи |
| title | string | Название задачи |
| hours | number | Планируемые часы |
| done | boolean | Статус выполнения |

Все задачи хранятся в массиве.

Начальные данные:

| id | title | hours | done |
|---|---|---:|---|
| 1 | Чтение | 2 | true |
| 2 | Практика | 4 | false |
| 3 | Повторение | 2 | false |

Идентификаторы новых задач должны быть уникальными в пределах списка.

## 3. Состояние приложения

Основные элементы состояния:

- `tasks` — массив всех задач.
- `filter` — выбранный фильтр: all, active, done.
- `form` — введённые пользователем название и часы.
- `errors` — ошибки валидации полей.

Итоговые показатели вычисляются из `tasks`, а не из отфильтрованного списка.

## 4. Операции

### Добавление

1. Получить название и часы из формы.
2. Проверить название после `trim`.
3. Проверить часы на пустоту, числовой тип, диапазон и шаг.
4. При ошибке показать сообщение возле поля, сохранив ввод.
5. При успешной проверке создать задачу с уникальным `id` и `done = false`.
6. Добавить задачу в `tasks`.
7. Пересчитать показатели и обновить интерфейс.

### Удаление

1. Получить идентификатор удаляемой задачи.
2. Исключить её из `tasks`.
3. Пересчитать показатели.
4. Обновить интерфейс.

### Переключение выполнения

1. Найти задачу по `id`.
2. Инвертировать её поле `done`.
3. Пересчитать показатели.
4. Обновить интерфейс.

## 5. Валидация

### Название

- Применить `trim`.
- Проверить, что полученная строка непустая.

### Часы

- Сначала проверить, что значение не пустое.
- Преобразовать корректный ввод в число.
- Проверить, что значение является конечным числом.
- Проверить диапазон: `0.5 ≤ hours ≤ 24`.
- Проверить кратность 0,5.

В частности, 0,5; 1; 1,5 и 24 допустимы, а пустая строка, -1, 0, 0,3 и 24,5 недопустимы.

Ошибки показываются рядом с полями. При неуспешной проверке задача не добавляется и значения формы не сбрасываются.

## 6. Вычисление прогресса

Определения:

- `totalHours = сумма hours для всех tasks`
- `doneHours = сумма hours для tasks с done = true`

Если `totalHours > 0`:

`progress = Math.round(100 * doneHours / totalHours)`

Иначе:

`progress = 0`

### Пример 1. Начальное состояние

- Всего: 2 + 4 + 2 = 8 ч.
- Выполнено: 2 ч.
- Прогресс: round(100 × 2 / 8) = 25%.

### Пример 2. Практика выполнена

- Всего: 8 ч.
- Выполнено: 2 + 4 = 6 ч.
- Прогресс: round(100 × 6 / 8) = 75%.

### Пример 3. Пустой список

- Всего: 0 ч.
- Выполнено: 0 ч.
- Прогресс: 0%.

Деление на ноль не выполняется.

## 7. Фильтрация

Фильтр применяется только при формировании видимого списка.

| Фильтр | Условие |
|---|---|
| all | Все задачи |
| active | done = false |
| done | done = true |

Переключение фильтра не изменяет `tasks`.

Показатели `totalHours`, `doneHours` и `progress` рассчитываются независимо от выбранного фильтра.

## 8. Интерфейс

Страница содержит:

- Заголовок мини-трекера.
- Форму с полями названия и часов.
- Кнопку добавления задачи.
- Сообщения об ошибках возле полей.
- Переключатель фильтра.
- Список задач с отметками выполнения и кнопками удаления.
- Итоговые часы и процент выполнения.

На ширине 390 px элементы должны размещаться без горизонтального переполнения.

## 10. Необязательное хранение

Если выбрано сохранение в `localStorage`:

- При наличии ранее сохранённых корректных данных используются они.
- Иначе используются стартовые задачи.
- После изменения задач предпринимается попытка сохранения.
- Ошибки чтения или записи обрабатываются.
- При недоступности хранилища показывается сообщение и работа продолжается в памяти.

## 11. Принцип обновления

После любого изменения данных:

1. Актуализируется массив `tasks`.
2. Пересчитываются общие показатели.
3. Применяется текущий фильтр для отображения списка.
4. Обновляется интерфейс.

Показатели не должны зависеть от количества видимых задач.
